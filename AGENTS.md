# AGENTS.md

## Purpose
This repository is a browser extension that enhances Confluence search and AI workflows.
Any agent working here must preserve cross-browser behavior, multi-domain Confluence support, and the two different AI modal runtimes.

## Non-Negotiable Requirements
1. The code must work in both Chromium-based browsers and Firefox.
2. The code must work with any Confluence domain configured by the user (no hardcoded tenant assumptions).
3. Be careful with AI modal changes: there are two contexts with subtle differences.

## Runtime Architecture
- `background/background.js`
  - Handles tab injection, host-permission checks, DB message RPC, and OpenAI proxy requests.
  - Uses feature detection for script injection (`chrome.scripting.executeScript` with fallback to `chrome.tabs.executeScript` for Firefox/MV2 compatibility).
- `extension/content/content.js`
  - Lightweight bootstrap injected into Confluence pages.
  - Loads built content bundle (`content/content-main.js`).
- `ui/src/contentApp.jsx`
  - Runs inside the Confluence page (content-script UI).
  - Renders floating launcher.
  - Opens AI modal as an iframe to `views/index.html?mode=content-modal...`.
  - Provides postMessage bridge for Confluence REST/image fetches.
- `ui/src/App.jsx`
  - Main views UI composition layer.
  - Wires feature controllers + presentational sections.
  - Also runs in `mode=content-modal` when embedded from content script.
- `ui/src/features/app/controllers/*`
  - `useSearchResultsController`: search/filter/pagination/tree-table lifecycle.
  - `useAiSummaryController`: AI modal state machine for both views and content-modal.
  - `useSavedSearchesController`: saved-search CRUD + related dialogs.
- `ui/src/features/app/utils/*`
  - Pure helpers extracted from `App.jsx` (query/tree/table/url/html/storage logic).
- `ui/src/components/AiModal.jsx`
  - Shared AI modal UI used by both the views page and content-modal mode.
- `ui/src/services/confluenceApi.js`
  - Confluence REST access with base URL fallback candidates and host-bridge support for content-modal mode.

## Browser Compatibility Rules (Chromium + Firefox)
- Do not assume Chrome-only MV3 APIs are always available.
- Keep runtime feature checks/fallbacks intact when touching background or permission logic.
- Keep `chrome.*` API usage compatible with Firefox WebExtension behavior.
- If manifest-related behavior changes, verify both targets:
  - Chrome dist is MV3 (`dist/chrome/manifest.json`)
  - Firefox dist is MV2 (`dist/firefox/manifest.json`) generated by `scripts/build-dist.mjs`

## Confluence Domain Rules (Any Domain)
- Domain access is user-configured in Options (`domainSettings`) and granted via optional host permissions.
- Never hardcode specific Confluence domains, paths, or tenant assumptions.
- Preserve base URL flow and fallbacks:
  - content page detection (`detectConfluenceBaseUrl`)
  - views/query param `baseUrl`
  - REST candidate fallbacks (`/wiki`, origin, context path)
- Keep requests credentialed where required (`credentials: 'include'`) for Confluence session auth.

## AI Modal: Two Contexts, Different Constraints
### 1) Views page modal
- Opened directly inside `views/index.html` from tree/table results.
- Can fetch Confluence APIs directly from the extension page context when permissions allow.

### 2) Content-page modal (`mode=content-modal`)
- Opened inside iframe from Confluence page via `contentApp.jsx`.
- Must rely on the host bridge (`postMessage`) for Confluence REST/image fetches.
- Bridge security checks (allowed origins, `/rest/api/` restrictions) are intentional and must not be weakened.
- The host also sends validated modal bounds for iframe masking and validated light/dark theme updates. Preserve source, parent-window, and origin validation for these messages.
- The modal follows the Confluence page theme by default; an explicit `syncThemeToConfluencePage: false` setting makes it use the extension theme instead.
- Close flow is cross-frame (`enhanced-ai-modal-close`) and must remain functional.

When changing AI flows/components/services, test both contexts explicitly.

## Source of Truth and Build Outputs
- Edit source files only:
  - `ui/`, `background/`, `extension/`, `shared/`, `scripts/`, root `manifest.json`
- Do not hand-edit generated output directories:
  - `.build/`
  - `dist/`

## Validation Checklist After Changes
1. `npm --prefix ui install` (if dependencies changed).
2. `npm --prefix ui run test`.
3. `npm run build:dist:checked`.
4. Manual smoke test in both Chrome and Firefox:
   - Save domain settings + permission prompts.
   - Open Confluence page and verify floating launcher injection.
   - Open views page and verify search, tree/table, and infinite loading.
   - Open AI modal from views and from Confluence content page.
   - Generate summary + follow-up Q&A in both browsers.

Notes:
- Agents should not skip `npm --prefix ui run test` when touching `ui/src/App.jsx`, `ui/src/features/app/**`, or shared UI services used by those flows.
- If tests cannot run (environment/tooling/network), the agent must state that explicitly in its final report.

## High-Risk Files
- `ui/src/App.jsx` (top-level orchestration; incorrect wiring can break multiple flows)
- `ui/src/features/app/controllers/useSearchResultsController.js` (search lifecycle + pagination)
- `ui/src/features/app/controllers/useAiSummaryController.js` (AI modal + content-modal bridge-sensitive behavior)
- `ui/src/features/app/controllers/useSavedSearchesController.js` (saved-search state + dialogs)
- `ui/src/contentApp.jsx` (content-runtime and bridge logic)
- `ui/src/services/confluenceApi.js` (fetch fallback + bridge behavior)
- `background/background.js` (permissions, injection, DB, OpenAI runtime)

Prefer small, targeted edits and verify behavior end-to-end when touching these.
